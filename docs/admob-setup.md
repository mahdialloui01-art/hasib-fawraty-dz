# إعداد الإعلانات عبر AdMob

هذه الصفحة توضح إكمال إعداد الإعلانات في تطبيق «حاسب فاتورتي DZ».

## ما تم دمجه في التطبيق

- Google Mobile Ads SDK (GMA Next-Gen) الإصدار `1.6.0`.
- Google User Messaging Platform (UMP) الإصدار `4.0.0` لإدارة الموافقة وخيارات الخصوصية.
- إعلان بانر متجاوب أعلى شريط التنقل، ويختفي أثناء شاشة إدخال بيانات الفاتورة والحساب.
- نسخة Debug تستخدم معرّفات الاختبار الرسمية من Google فقط.
- نسخة Release لا تعرض إعلانات حتى يتم توفير معرّفي AdMob الحقيقيين.

## إنشاء معرّفات AdMob

1. أنشئ أو افتح حساب AdMob.
2. أضف تطبيق Android جديداً بمعرّف الحزمة `dz.hasibfawraty.app`.
3. انسخ **AdMob App ID** الذي يكون شكله `ca-app-pub-xxxxxxxxxxxxxxxx~yyyyyyyyyy`.
4. أنشئ وحدة إعلانية من نوع **Banner** وانسخ **Ad unit ID** الذي يكون شكله `ca-app-pub-xxxxxxxxxxxxxxxx/zzzzzzzzzz`.
5. أعد فحص اسم الحزمة وتأكد أن التطبيق المسجل هو تطبيقك الصحيح.

## إضافة المعرّفات إلى GitHub

في المستودع افتح Settings ثم Secrets and variables ثم Actions، وأنشئ Repository secrets التالية:

| اسم السر | القيمة المطلوبة |
| --- | --- |
| `ADMOB_APP_ID` | معرّف تطبيق AdMob الذي ينتهي بعلامة `~` ورقم |
| `ADMOB_BANNER_AD_UNIT_ID` | معرّف وحدة بانر AdMob الذي يحتوي `/` |

يجب ضبط القيمتين معاً. لا تضع كلمة مرور حساب AdMob أو مفاتيح التوقيع في هذين الحقلين. لا تشارك بيانات تسجيل الدخول مع أي شخص.

## الخصوصية وGoogle Play

- من AdMob، راجع قسم Privacy & messaging وأنشئ رسائل الخصوصية المطلوبة لمستخدمي المناطق التي تنطبق عليها المتطلبات.
- يطلب التطبيق تحديث حالة الموافقة عند كل تشغيل، ولا يطلب الإعلانات إلا عندما تسمح حالة UMP بذلك.
- يظهر رابط خيارات الخصوصية داخل إعدادات التطبيق فقط عندما تعلن UMP أن نقطة الدخول مطلوبة.
- حدّث نموذج Data safety في Play Console بناءً على بيانات SDK الإعلاني: عنوان IP (وقد يُستخدم لاستنتاج الموقع التقريبي)، تفاعلات التطبيق، بيانات التشخيص، ومعرّفات الجهاز والحساب، وأغراض الإعلان والتحليل ومنع الاحتيال. راجع أنواع البيانات والأغراض الفعلية في إرشادات Google الحالية قبل الإرسال. راجع إفصاح Google الحالي قبل الإرسال.
- تأكد أن صفحة سياسة الخصوصية العامة تعمل من متصفح خارج GitHub قبل وضع رابطها في Play Console.

## اختبار النشر

- شغّل GitHub Actions وتأكد من نجاح `testDebugUnitTest` و`assembleDebug` و`bundleRelease`.
- اختبر نسخة Debug فقط بإعلانات الاختبار، ولا تضغط على الإعلانات لأغراض التجربة.
- بعد إضافة معرّفات AdMob الحقيقية، أنشئ AAB Release جديداً وتأكد من أنه يستخدم معرّفات التطبيق والوحدة الصحيحة.
- لا ترفع نسخة Release إلى Play Console قبل مراجعة سياسة الخصوصية ونموذج Data safety وإعدادات الجمهور والإعلانات.

## ملاحظات

- رفع الحد الأدنى إلى Android 7.0 (`minSdk 24`) يعني أن Android 6.0 والأقدم لم تعد مدعومة.
- وجود الإعلانات لا يضمن دخلاً ثابتاً؛ يعتمد الدخل على عدد المستخدمين ومرات الظهور والبلدان ومعدل التعبئة وسياسات AdMob.
- الإعلانات لا ينبغي أن تعيق إدخال قراءات العدادات أو حساب الفاتورة.
